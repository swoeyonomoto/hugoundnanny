# Project architecture

- Scope page-specific visual systems beneath a page root class so shared sections and legacy pages remain unchanged.
- Keep gallery commerce as a no-payment request flow: temporary selections use browser storage and final requests go through Formspree, because payment is completed later by an emailed PayPal link.
- Keep gallery administration behind Supabase Auth and a server-enforced separate admin role; public gallery pages only read active gallery configuration.
- Store editable gallery and print-product presentation data in Supabase; use bundled assets only as visual fallbacks so admin changes remain authoritative.
- Store per-gallery film booking extras as a metadata record in the existing films JSON, preserving it when editing films; use the existing request inbox without schema changes or payment integration.
- Use the shared galleryPreview helper for compressed gallery thumbnails; reserve larger sizes for opened photos and intentional display images.
- Create galleries as inactive drafts through existing RLS-protected configuration; play public Dropbox file links as inline HTML video while retaining Wistia so no tokens or Dropbox pages reach the gallery presentation.
- Pair Cormorant Garamond Light headlines with Inter body text on all public pages, while preserving independently scoped Asia and gallery compositions and the admin typography.
- Keep Film Guide presentation in dedicated components and page-scoped styles; its reference typography is an intentional isolated exception so existing public pages remain unchanged.
- Keep the live Film Guide overview in a dedicated presentation component using existing price lines and loaded settings so clearer descriptions never change pricing.
- Keep Film Guide answer transitions and pricing in pure tested functions, with configurable settings independent of presentation; this prevents summary, confirmation and handoff totals from diverging.
- Keep Film Guide bilingual chapter copy in a dedicated data module and render only supported italic/bold markers as React elements; this preserves the supplied wording without unsafe HTML or pricing changes.
- Keep public Film Guide persistence behind existing start/load/save/send functions and token-scoped local recovery; never query private leads from public pages because tokens must not bypass server validation.
- Never redirect a failed personal Film Guide link to a blank guide or create a replacement record; show a retryable error to protect the couple's saved configuration.
- Keep the Film Guide loader token-scoped with bounded input and explicit public fields; readable admin slugs and legacy random tokens must both resolve without revealing admin-only data.
- Keep Film Guide saves token-scoped with the same readable-slug and legacy-token validation as loading, bounded bodies and the supplied writable-field allowlist; custom links must save progress without granting admin-field access.
- Finalize Film Guides through the existing save endpoint with server-validated final details and an atomic completion timestamp; notify the existing inquiry inbox server-side without personal tokens or admin notes, keeping receipt independent of email delivery.
- Resolve admin discounts through the existing token load before public saves and local recovery; browser drafts must not overwrite couple-specific admin configuration.
- Use the existing Film Guide admin RPC before rendering admin tools and rely on existing RLS for all table and storage operations; UI checks alone never authorize access.
- Pass loaded settings through every Film Guide calculation, summary and handoff, and resolve clips from public configuration with bundled fallbacks; admin edits must remain authoritative.
- Keep Film Guide currency conversion presentation-only with a dated public reference rate and offline fallback; shared pure conversion functions keep the calculator, estimates and handoff consistent while stored estimates stay in EUR.
- Keep Clarity initialization and lifecycle scoped to the public Film Guide with a server-verified non-admin session; admin and unrelated pages must not record guide activity.
- Keep the admin workspace theme scoped to `.gallery-admin` and account settings in a separate view so public styling and gallery editing remain independent.
- Display stored lead estimates as saved estimates, not recomputed quotes, so admin reflects what was last saved by the couple; current calculations remain available in the plan detail.
- Keep cross-project synchronization pending until a secure, authorized integration exists in both projects; external tool links do not imply shared records or prices.
- Render Film Guide custom offers only from the server-returned enabled offer, accept them through the existing save endpoint, and keep offer price maths in a pure tested module; couples can never alter offer terms.
